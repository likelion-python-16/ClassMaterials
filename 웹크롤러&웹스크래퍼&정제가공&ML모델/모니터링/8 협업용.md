`1)` CI: django-docker-ci.yml
역할: Docker로 빌드 → 컨테이너에서 테스트 → 서버 실행해서 /metrics 스모크.
```yml
name: Django CI (Docker + /metrics smoke)

on:
  push:
    branches: [ main, dev ]
  pull_request:
    branches: [ main, dev ]

jobs:
  build-test-metrics:
    runs-on: ubuntu-latest

    steps:
    - name: Checkout
      uses: actions/checkout@v4

    - name: Set up Buildx
      uses: docker/setup-buildx-action@v3

    # Django Dockerfile이 repo 루트에 있다는 가정
    # (다르면 context/path를 AIRestaurant로 바꾸세요)
    - name: Build app image
      run: docker build -t django-test-image .

    - name: Run unit tests inside container
      run: docker run --rm django-test-image python manage.py test -v 2

# /metrics 스모크: ENABLE_METRICS=true 로 서버 띄우고 metrics 확인
    - name: Smoke /metrics
      env:
        ENABLE_METRICS: "true"
      run: |
        docker run -d --rm --name django-ci \
          -p 8900:8900 \
          -e ENABLE_METRICS=${ENABLE_METRICS} \
          django-test-image \
          python manage.py runserver 0.0.0.0:8900

        # 대기 후 /metrics 체크
        for i in {1..20}; do
          curl -fsS http://127.0.0.1:8900/metrics && break
          echo "waiting metrics..."; sleep 3
        done
        docker logs django-ci --tail 50
        docker stop django-ci
```

`2)` 서버(EC2)용 Compose: observability/docker-compose.yml
역할: 하나의 Compose로 Django 앱 + Prometheus + Grafana를 같은 네트워크에서 실행.  
Prometheus 타깃은 `django:8000` (서비스 이름) 사용 → 리눅스 EC2에서 안정적.
```yml
# observability/docker-compose.yml
services:
  django:
    image: ghcr.io/OWNER/REPO:latest   # ← CI에서 빌드/푸시한 이미지 태그 사용
    container_name: django-app
    env_file:
      - ./app.env                      # 서버용 환경변수 파일(아래 참고)
    command: python manage.py runserver 0.0.0.0:8000
    ports:
      - "8000:8000"                    # 외부 접근 필요 시
    depends_on: []
    restart: unless-stopped

  prometheus:
    image: prom/prometheus:latest
    container_name: prometheus
    ports: ["9090:9090"]
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml:ro
      - promdata:/prometheus
    depends_on: [ django ]
    restart: unless-stopped

  grafana:
    image: grafana/grafana:latest
    container_name: grafana
    ports: ["3000:3000"]
    volumes:
      - grafdata:/var/lib/grafana
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=${GF_ADMIN_PASSWORD:-admin}
    depends_on: [ prometheus ]
    restart: unless-stopped

volumes:
  promdata:
  grafdata:
```

`3)` CD: deploy-ec2-compose.yml (기존 docker-deploy.yml 개선)
역할: EC2에 Compose 파일과 env를 업로드 → `docker compose up -d`로 앱+모니터링 동시 배포.
```yml
name: Deploy (EC2 + docker compose)

on:
  push:
    branches: [ main ]
  workflow_dispatch:

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v4

    # (선택) GHCR 같은 레지스트리에 최신 이미지 빌드/푸시까지 포함하고 싶다면 여기에 추가
    # - name: Login to GHCR
    #   uses: docker/login-action@v3
    #   with:
    #     registry: ghcr.io
    #     username: ${{ github.actor }}
    #     password: ${{ secrets.GITHUB_TOKEN }}
    # - name: Build & Push image
    #   run: |
    #     docker build -t ghcr.io/${{ github.repository_owner }}/REPO:latest .
    #     docker push ghcr.io/${{ github.repository_owner }}/REPO:latest

    - name: Set up SSH
      run: |
        mkdir -p ~/.ssh
        echo "${{ secrets.EC2_SSH_KEY }}" > ~/.ssh/id_rsa
        chmod 600 ~/.ssh/id_rsa
        ssh-keyscan -H ${{ secrets.EC2_HOST }} >> ~/.ssh/known_hosts

    # 서버의 배포 디렉터리(예: /srv/app)로 Compose와 env 동기화
    - name: Upload compose & env
      run: |
        scp -o StrictHostKeyChecking=no -i ~/.ssh/id_rsa \
          observability/docker-compose.yml \
          observability/prometheus.yml \
          ${{ secrets.EC2_USER }}@${{ secrets.EC2_HOST }}:/srv/app/
        # app.env 내용은 시크릿으로 관리
        ssh -i ~/.ssh/id_rsa ${{ secrets.EC2_USER }}@${{ secrets.EC2_HOST }} \
          "printf '%s\n' \"$ENV_CONTENT\" > /srv/app/app.env"
      env:
        ENV_CONTENT: ${{ secrets.APP_ENV_CONTENT }}  # 서버용 env 전체(멀티라인)

    - name: Compose up on EC2
      run: |
        ssh -o StrictHostKeyChecking=no -i ~/.ssh/id_rsa \
          ${{ secrets.EC2_USER }}@${{ secrets.EC2_HOST }} \
          'cd /srv/app && docker compose up -d'
```
필요한 Secrets
- `EC2_HOST`, `EC2_USER`, `EC2_SSH_KEY`(프라이빗 키)
- `APP_ENV_CONTENT`(서버용 `.env` 전체)
- (선택) `GF_ADMIN_PASSWORD`, 레지스트리 자격증명 등

FastAPI 계측
`fastdining_api/src/app.py`
```python
import os, time
from fastapi import FastAPI, Request, Response

app = FastAPI()

# 토글(문제 생기면 꺼둘 수 있도록)
ENABLE_METRICS = os.getenv("ENABLE_METRICS", "true").lower() == "true"

if ENABLE_METRICS:
    from prometheus_client import Counter, Gauge, Histogram, generate_latest, CONTENT_TYPE_LATEST

    REQ = Counter("app_requests_total", "총 HTTP 요청 수", ["endpoint","method","status"])
    INPROG = Gauge("app_inprogress_requests", "현재 처리 중 요청 수")
    LAT = Histogram("app_request_duration_seconds", "요청 처리 시간(초)", ["endpoint","method"])

    @app.middleware("http")
    async def _metrics_mw(req: Request, call_next):
        with INPROG.track_inprogress():
            start = time.perf_counter()
            resp: Response = await call_next(req)
            dur = time.perf_counter() - start
            REQ.labels(req.url.path, req.method, str(resp.status_code)).inc()
            LAT.labels(req.url.path, req.method).observe(dur)
            return resp

    @app.get("/metrics")
    def metrics():
        return Response(generate_latest(), media_type=CONTENT_TYPE_LATEST)

@app.get("/")
def root():
    return {"ok": True}
```

협업 시 규칙
- Prometheus/Grafana는 공용 1세트 → `observability/` 폴더에서만 관리
- 각 서비스는 /metrics만 노출, 라벨은 팀 표준(예: `endpoint,method,status`)
- 포트 구분:
    - 컨테이너 내부 포트(uvicorn `--port 80`)
    - 호스트 공개 포트(compose `8000:80`)
    - Prometheus 타깃은 호스트 공개 포트를 사용(`host.docker.internal:8000/8900`)
- Django는 `ALLOWED_HOSTS`에 `host.docker.internal` 포함(WSL이면 IP도)
- 문제 나면 `ENABLE_METRICS=false`로 바로 토글 가능

`1)` django-ci.yml (당신의 파일을 다듬은 버전)
    - 작업 디렉터리를 `AIRestaurant`로 고정
    - MySQL 서비스 컨테이너 헬스체크 후 마이그레이션/테스트
    - (선택) `/metrics` 스모크 단계 추가 가능

```yml
name: django-ci
on:
  pull_request:
    paths: ['AIRestaurant/**', '.github/workflows/django-ci.yml']
  push:
    branches: [ main, dev ]
    paths: ['AIRestaurant/**']

jobs:
  test:
    runs-on: ubuntu-latest

    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: root
          MYSQL_DATABASE: restaurant_db
        ports: ['3306:3306']
        options: >-
          --health-cmd="mysqladmin ping -h localhost -uroot -proot --silent"
          --health-interval=10s --health-timeout=5s --health-retries=10

    defaults:
      run:
        working-directory: AIRestaurant

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with: { python-version: '3.12' }

      - name: System deps for mysqlclient
        run: sudo apt-get update && sudo apt-get install -y default-libmysqlclient-dev

      - name: Install Python deps
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt

      - name: Wait for MySQL
        run: |
          for i in {1..20}; do
            mysqladmin ping -h 127.0.0.1 -uroot -proot --silent && break
            echo "waiting mysql..."; sleep 3
          done

      - name: Migrate
        env:
          DB_NAME: restaurant_db
          DB_USER: root
          DB_PASSWORD: root
          DB_HOST: 127.0.0.1
        run: python manage.py migrate --noinput

      - name: Run tests
        env:
          DB_NAME: restaurant_db
          DB_USER: root
          DB_PASSWORD: root
          DB_HOST: 127.0.0.1
        run: python manage.py test -v 2

  # (선택) /metrics 스모크
  metrics-smoke:
    runs-on: ubuntu-latest
    needs: test
    defaults:
      run:
        working-directory: AIRestaurant
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.12' }
      - run: |
          pip install -r requirements.txt
          nohup python manage.py runserver 0.0.0.0:8900 &
          sleep 3
          curl -fsS http://127.0.0.1:8900/metrics | head
```
