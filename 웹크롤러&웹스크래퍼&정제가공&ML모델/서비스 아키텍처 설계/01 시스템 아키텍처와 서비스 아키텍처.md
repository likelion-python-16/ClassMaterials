모든 사용자 유형(Users, Administrators, Data/ML Engineers)은 브라우저(Chrome 등)를 통해 시스템에 접근한다는 공통점을 갖고 있습니다.
![[Pasted image 20250727143741.png]]
클라이언트 인터페이스는 통일되어 있으며, 역할에 따라 뒤쪽에서 접속하는 서버나 기능이 달라집니다.


NGINX는 각 사용자(Users, Administrators, Data/ML Engineers)가 접속할 때 가장 먼저 마주하는 "진입 지점" 역할을 담당합니다.
![[Pasted image 20250727143755.png]]
NGINX란?
NGINX(엔진엑스)는 가볍고 빠른 웹 서버이자, 리버스 프록시(reverse proxy), 로드 밸런서(load balancer), HTTP 캐시 서버로 널리 사용되는 오픈소스 소프트웨어입니다.

###### 핵심특징
| 특징            | 설명                                       |
| ------------- | ---------------------------------------- |
| 고성능           | 동시 접속 처리에 최적화되어 있어 트래픽이 많아도 빠르고 안정적      |
| 비동기 이벤트 기반 구조 | Apache보다 더 많은 연결을 효율적으로 처리               |
| 다기능           | 웹 서버, 프록시 서버, 정적 파일 서빙, SSL 처리, 로드 밸런싱 등 |
| 가볍고 빠름        | CPU/메모리 사용이 적어 클라우드/컨테이너 환경에 적합          |
###### 주요역할
| 역할       | 예시                                      |
| -------- | --------------------------------------- |
| 웹 서버     | HTML, CSS, JS 같은 정적 파일을 클라이언트에 직접 제공    |
| 리버스 프록시  | 클라이언트 요청을 내부 서버(FastAPI, Django 등)에 전달  |
| 로드 밸런서   | 여러 서버에 트래픽을 분산시켜 성능 향상                  |
| SSL 처리   | HTTPS 보안 연결 적용 (Let's Encrypt 등과 함께 사용) |
| 정적 파일 서빙 | 이미지, JS, CSS 파일 등을 빠르게 서빙               |

Frontend Area
이 영역은 사용자 인터페이스(UI)와 API 통신을 처리하는 부분으로, 전체 시스템의 "프론트엔드 개발 스택"을 구성합니다.
![[Pasted image 20250727143836.png]]

###### 구성요소
| 구성 요소   | 설명                                                        |
| ------- | --------------------------------------------------------- |
| NGINX   | 사용자의 웹 요청(HTML/CSS/JS)을 빠르게 응답하기 위해 정적 빌드 파일(React 등)을 서빙 |
| Node.js | 프론트엔드 개발 환경 구성 (JS 런타임), 빌드/패키징에 사용                       |
| Vite    | 모던 프론트엔드 개발 툴. React 등의 자바스크립트 앱을 빠르게 개발/번들링              |
| React   | 실제 사용자 화면을 구성하는 라이브러리 (SPA 기반 UI 개발)                      |
| Axios   | 프론트엔드와 백엔드 간의 HTTP 통신을 담당하는 라이브러리 (API 호출)                |

전체흐름(프론트엔드 중심)
```
[사용자 브라우저]
     ↓ 요청
[NGINX (정적 빌드 파일 전달)]
     ↓ HTML/CSS/JS
[React 앱 실행]
     ↓
[Axios로 API 요청 (GET/POST 등)]
     ↓
[백엔드 NGINX → FastAPI 또는 Django로 전달]
```
- 정적 파일 제공: React 앱은 Vite로 빌드된 뒤, NGINX가 정적 파일(HTML, JS, CSS 등)을 서빙합니다.
- 실행된 React 앱은 Axios를 이용해 백엔드 API(FastAPI, Django 등)에 데이터를 요청합니다.
- 백엔드 응답을 받아 React가 사용자에게 데이터를 보여줍니다.
웹 브라우저에서 보이는 화면(UI)을 만들고, 서버와 연결하여 데이터를 가져오는 프론트엔드 전체 구성 요소입니다.  
React + Vite로 구성된 UI를 NGINX가 서빙하고, Axios를 통해 백엔드 API와 통신합니다.

관리자(Admin) 및 데이터/머신러닝(Data/ML) 영역
![[Pasted image 20250727143852.png]]
#### Admin Area (관리자 영역)
| 구성 요소    | 설명                                       |
| -------- | ---------------------------------------- |
| NGINX    | 관리자 웹 요청을 받아 내부 Django 앱으로 전달            |
| Gunicorn | Django 앱을 실행하는 WSGI 서버                   |
| Django   | 관리자용 웹 인터페이스(예: Django Admin) 및 운영 도구 제공 |
이 영역은 운영자(관리자)가 웹 브라우저를 통해 서비스 상태 확인, 사용자 관리, 콘텐츠 관리 등을 할 수 있게 해줍니다.

###### Data / ML Area (데이터 및 머신러닝 영역)
| 구성 요소            | 설명                                   |
| ---------------- | ------------------------------------ |
| Jupyter Notebook | 브라우저 기반의 데이터 분석·머신러닝 개발 환경           |
| Scikit-learn     | Python 기반의 머신러닝 라이브러리 (분석, 예측 모델링 등) |
이 영역은 데이터 과학자나 머신러닝 엔지니어가 데이터 분석, 모델 학습, 성능 검증, 모델 서빙 준비 등을 수행하는 공간입니다.

전체 흐름 정리
```
[관리자 또는 ML 엔지니어 브라우저]
    ↓
[NGINX (Admin/Data 영역)]
    ↓
    ├─ Gunicorn → Django Admin
    └─ Jupyter Notebook → scikit-learn 분석 수행
```
- 관리자는 웹 대시보드(Django Admin)에서 데이터/사용자/시스템을 관리합니다.
- ML 엔지니어는 Jupyter Notebook에서 데이터 탐색 및 모델링을 수행하며,  
    필요 시 백엔드(FastAPI)나 DB(MySQL)와 연동합니다.

---
Backend Area" (백엔드 영역)
이 영역은 프론트엔드 또는 외부 요청이 들어왔을 때 실제 비즈니스 로직을 처리하고, 데이터베이스 및 머신러닝 로직과 연결되는 핵심 처리 구간입니다.
![[Pasted image 20250727143926.png]]

###### Backend Area 구성 요소 설명
| 구성 요소        | 역할 및 설명                                               |
| ------------ | ----------------------------------------------------- |
| NGINX        | 리버스 프록시 역할. 외부 요청을 받아 내부 Uvicorn 서버로 전달. 정적 파일도 서빙 가능 |
| Uvicorn      | ASGI 서버로서 FastAPI 애플리케이션을 실행. 고속 비동기 처리를 지원           |
| FastAPI      | 실제 비즈니스 로직/API 작성 프레임워크. 사용자 요청 처리, 모델 호출, DB 연결 등    |
| Scikit-learn | 머신러닝 모델 로딩 및 예측 처리. FastAPI를 통해 모델을 서비스 형태로 제공        |

전체 요청 처리 흐름
```
[브라우저 또는 프론트엔드 Axios 요청]
     ↓
[NGINX (백엔드 프록시)]
     ↓
[Uvicorn (ASGI 서버)]
     ↓
[FastAPI (API 로직)]
     ↓
 - DB (MySQL)와 연결
 - ML 모델 (scikit-learn) 호출 및 결과 반환
```
- 사용자가 React 프론트엔드에서 Axios로 `/predict` 요청을 보냄
- NGINX가 요청을 받아 FastAPI로 전달
- FastAPI가 scikit-learn 모델을 로딩하여 입력 데이터에 대해 예측 수행
- 예측 결과를 JSON으로 응답
- 사용자 브라우저에서 결과 확인
이 Backend Area는 모든 사용자 요청을 실제로 처리하고, 예측하거나 데이터를 가져오는 실질적 핵심 로직이 위치한 영역입니다.  
고성능 처리를 위해 FastAPI + Uvicorn 조합이 사용되며, 머신러닝 모델과 데이터베이스를 모두 연결해 응답을 생성합니다.

---
Backend Area의 ML 모델 처리와 리소스/데이터 영역 (Resource Area, Database Area)입니다. 이 부분은 서비스에서 데이터를 저장하고, 분석하거나 예측 결과를 반환하는 핵심 인프라에 해당합니다.
![[Pasted image 20250727143939.png]]

강조된 구성요소 설명
`1.` scikit-learn (Backend Area)
- 역할: FastAPI와 함께 머신러닝 모델을 실행 (예: 예측 요청 처리)
- Scikit-learn은 Python 기반의 머신러닝 라이브러리로, FastAPI API 내부에서 예측 모델을 로드하고 사용자 입력값에 대해 결과를 반환하는 데 사용됩니다.
    
- 예측 과정:
    1. API 요청 수신 (예: `/predict`)
    2. scikit-learn 모델 로드
    3. 입력값으로 예측 수행
    4. 예측 결과 반환

`2.` MySQL (Database Area)
- 역할: 사용자 정보, 예측 기록, 콘텐츠 데이터 등 구조화된 데이터 저장소
- FastAPI, Django 등 여러 서버에서 공통적으로 연결되는 핵심 데이터베이스
- 일반적인 사용 예:
    - 사용자 입력 데이터 저장
    - 모델 예측 결과 로그 저장
    - 관리자 페이지에서 통계/분석용 데이터 조회

`3.` File System (Resource Area)
- 역할: 이미지, 문서, 모델 파일, 정적 리소스 등의 비정형 데이터 저장
- 예시:
    - 업로드된 이미지 파일
    - 학습된 ML 모델(pkl, joblib 등)
    - 리포트, 로그, 분석 결과
---
데이터 흐름 예시
```
[사용자 입력 → FastAPI API 호출 (/predict)]
    ↓
[FastAPI] → [scikit-learn 모델로 예측 수행]
    ↓
[예측 결과 저장 또는 조회] → MySQL
                      ↘︎ 관련 리소스 접근 → File System
```
이 빨간 박스는 AI 모델 예측과 데이터 저장이 실제로 수행되는 핵심 실행/저장소 영역입니다.  
FastAPI + scikit-learn 조합으로 예측 API 제공,  
MySQL과 File System은 이를 기록하고 관련 리소스를 관리하는 핵심 백엔드 인프라 역할을 합니다.

API로 제공하지 않을 기능들

`1.` User / Auth 영역
- 제외 기능:
    - `Create` (회원 생성)
        - 인증/회원가입으로 대체됨
    - `Permission Management` (권한 관리)
        - 관리자 기능이므로 API에서 직접 노출하지 않음

`2.` Restaurant 영역
- 제외 기능:
    - `Create` (음식점 생성)
    - `Image Upload` (이미지 업로드)
    - `Info Update` (음식점 정보 수정)
    - `Delete` (삭제)
        - 이유: 사용자가 수동으로 해야 하는 작업이므로 관리자 페이지에서는 API에서 제외

`3.` Review / BlogReview / Article 영역
- 제외 기능:
    - `Create` (콘텐츠 생성)
    - `Image Upload` (리뷰 이미지 업로드)
    - `Info Update` (수정)
    - `Delete` (삭제)
        - 이유: 유저가 직접 작성/삭제해야 하므로 관리자 페이지API에서 처리하지 않음

별도의 리소스화가 필요한 부분
해당 리소스들에서 특징적으로 제공되는 기능으로 통합이 가능
리뷰의 생성 별점 이미지 업로드는 리뷰생성이라는 엔드포인트로 통합할수 있음.
![[Pasted image 20250727144135.png]]

| 색상          | 의미                      | FastAPI 설계에서의 이유                                                                        |
| ----------- | ----------------------- | --------------------------------------------------------------------------------------- |
| 🔴 빨강(제외)   | API로 외부에 노출하지 않음        | - 관리자만 수행해야 하는 기능<br>- 보안상 API로 제공 시 위험<br>- 일반 유저가 호출할 필요 없음<br>- Django Admin 등으로만 처리 |
| 🟢 초록(리소스화) | 별도의 엔드포인트로 분리 필요        | - DB에서 독립적 관리가 필요한 자원<br>- CRUD가 필요한 구조<br>- 예: `tags`, `menus`, `categories`           |
| 🔵 파란(통합)   | 다른 API 요청과 함께 묶어서 처리 가능 | - 굳이 따로 만들 필요 없음<br>- 생성 요청에 함께 포함 가능 (이미지 업로드 등)<br>- Query Parameter로 해결 가능 (검색/추천 등) |
